# Figure 2 插入窗口后分析

本次仅重新分析已有正式测量，没有新推理实验。源数据为 `artifacts/two-node-phase8-figure2-large-batch-evidence/` 的 `formal` 与 `formal-independent`；150 个 trial 中有 100 次干扰，包含 12,795 条背景请求、1,637,760 个单 token SSE 事件。分析得到 12,578 条可按完整 batch 配对的步骤记录。所有读取的源文件与原始校验清单匹配。

## 结论

用户提出的平均稀释问题得到现有数据支持：把一次混合步骤的停顿平均到整个 128-token 请求，会将数倍的局部间隔增加压低为几个百分点。原整段 TPOT 数值本身仍成立，但它不能直接表达单次插入的瞬时干扰。

以下三列均使用客户端 token 到达间隔；先对每次 trial 与相同重复的 baseline 配对，再汇总五次重复的均值与样本标准差。不是直接用总体均值相除，也不是置信区间。

## 干扰持续多久

同时观察三种耗时：模型输出交回调度器前的墙钟耗时、完整引擎 iteration 的墙钟耗时、客户端 token 到达间隔。它们涵盖的主机/调度/传输处理范围不同，不能互称为 GPU kernel 耗时。

以固定的描述性回归规则（阈值为 1 ms、baseline 中位数的 5%、3 倍稳健标准差三者最大值；连续五步回到阈值内）检查：

| 共享历史 90 次干扰 | 首次连续回归区间始于 step 1 | 首次回归区间开始位置范围 | 回归区间之后仍有越界的 trial |
|---|---:|---:|---:|
| 模型墙钟 | 86/90 | 1–3 | 41/90 |
| 完整引擎 iteration | 78/90 | 1–10 | 56/90 |
| 客户端 token 间隔 | 31/90 | 1–15 | 82/90 |

独立历史组 10 次干扰的模型墙钟和完整引擎首次回归均从 step 1 开始，客户端为 7/10。所有默认阈值下的 trial 都在观测范围内找到首次回归；仍保存右删失字段以避免对未来无回归样本强行指定结束时间。

这支持“主要模型执行停顿通常集中在混合步骤”的解释。客户端后续间隔更容易波动，不能先验把所有影响限定为一步。后面出现的越界可能包含正常波动、控制组波动、主机/观测停顿或干扰后效应，当前观测不能逐一证明因果。

以共享 batch 250 为例，full/append 的混合步骤客户端平均额外间隔为 203.22/207.22 ms；前五个间隔的累计额外延迟为 190.45/197.99 ms。后续有负差值和再次上升，因此累计值不应强制单调，也不应只累加正值。整段平均与局部窗口还受注入前和收尾阶段差异影响，不能把它们简单视为同一个窗口乘以不同系数。

默认 5% 阈值之外，还完整保存 3% 和 10% 的敏感性。共享组模型墙钟首次回归始于 step 1 的次数分别为 84/86/87，完整引擎为 77/78/81，客户端为 31/31/39。这些描述性规则均未用于裁剪绘图数据或挑选“漂亮”的重复。

## 方法与可复核性

插入点由 scheduler trace 中实际执行 1024-token prefill 的混合步骤定位。每条背景请求按同组、同 batch、同重复、同请求序号、相同输出 token 序号匹配纯 decode 控制；允许启动时间造成步骤中的输出序号不同。每个配对参考步骤必须也具有完整 batch。

固定窗口为 step 0 起的 1/5/16/32/64 步；另保存可匹配完整 batch 的全部后续窗口和原整段 TPOT。所有 trial 均覆盖 -5 到 +63。204 个部分 batch 步骤列入排除清单，固定窗口之外的完整步骤仍保留；累计图使用每组五次重复、两场景共同覆盖的范围，快照保留更多尾部点及实际 n。

每个 SSE token 事件都恰含一个 token，没有为批量事件插值。重新计算所有背景请求的整段 TPOT，并验证窗口内间隔之和等于首尾到达时间差。恢复规则对延迟回归、再次越界、未恢复及负偏移做了边界检查。派生验收见 `artifacts/phase8-figure2-window-analysis/verification.json`。
