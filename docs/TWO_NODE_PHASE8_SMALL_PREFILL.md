# Phase 8：256+32 小干扰 Figure 2 适配实验

本轮在单张 RTX 4090、Qwen2.5-7B 上测试背景 decode batch size 10、50、100、150、200、250。每条背景请求使用独立 256-token 历史、4-token 新增，输出 128 token。干扰请求使用 256-token历史和 32-token 新增：Append 复用 256-token 缓存并计算 32 token，Full 使用相同完整输入但冷缓存重算 288 token。三种场景均在背景请求输出至少 8 token 后插入干扰请求。

固定 `max_num_batched_tokens=2048`、`max_num_seqs=251`，显存利用率设为 0.90 以容纳 batch 250；先导验证 250 条背景在三种场景均完整重叠且无抢占。正式实验每点 3 次，共 54 trials、13,770 条请求，全部通过原始请求/SSE、缓存命中、实际计算量、完整 batch 和无抢占审计。

## 结果

| Batch | Decode only | Append | Full |
|---:|---:|---:|---:|
| 10 | 17.797 ± 0.016 | 17.813 ± 0.020 | 18.103 ± 0.249 |
| 50 | 21.079 ± 0.012 | 21.107 ± 0.021 | 21.280 ± 0.029 |
| 100 | 24.107 ± 0.215 | 24.063 ± 0.026 | 24.249 ± 0.004 |
| 150 | 28.320 ± 0.113 | 28.459 ± 0.171 | 28.584 ± 0.037 |
| 200 | 35.067 ± 0.130 | 35.653 ± 0.740 | 35.394 ± 0.317 |
| 250 | 39.297 ± 0.375 | 39.086 ± 0.102 | 39.317 ± 0.160 |

单位为背景 TPOT（ms/token），均值 ± 三次重复样本标准差。完整平均使用每条背景请求的全部 127 个 token 间隔，再平均请求和重复；不混入干扰 TTFT。

事件窗口额外提供 offset 0 起的 1、4、8、16 步窗口。窗口只保留三次重复均存在完整背景 batch 的窗口；76 个局部不完整步骤被排除并记录，未插值。全程平均仍保留所有成功请求。

这些结果显示 32-token 干扰的平均影响很小，Full 相比 Append 的差异也明显小于此前 1,024-token/16K 历史诊断。这是当前硬件、模型和调度配置上的适配结果，不等同于论文 H100/Llama Figure 2 的精确复现。
