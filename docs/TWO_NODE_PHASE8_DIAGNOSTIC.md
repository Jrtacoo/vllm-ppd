# Phase 8：历史长度与调度预算诊断

日期：2026-11-16。已完成用户批准的小规模诊断；未启动全量 batch 扫描。

## 结论

长历史重算是当前 Full 累计延迟明显较大的主要来源。降低 token budget 把一次长停顿拆成多个短停顿，显著降低最长模型步骤，但不会消除历史重算；对整段平均 TPOT 的改善需与峰值改善区分。

在本轮三个 batch 点上，缩短历史明显缩小了 Full 与纯 decode 的差距，但没有证实“低 batch 几乎无影响、高 batch 才显著增长”的论文式转折。仅按图注字面条件让两类 prefill 都计算 1,024 token 时，Full 与 Append 接近，也没有恢复论文中的明显分离。因此不能把缩短历史或分块后曲线更接近基线，宣称为 Figure 2 已复现。

## 配置与控制变量

- 既有镜像 `ppd-qwen25:source-cu129`，单 dcn10 RTX 4090，Qwen2.5-7B BF16、FA2、eager、前缀缓存。未新建镜像。
- 同上下文 2×2 因子实验：历史 2,048／16,384，单步 token budget 2,048／17,664。新输入恒为 1,024，Full 冷缓存重算历史＋新输入，Append 复用历史。
- 图注字面条件单独测试：预算 2,048，Full 无历史计算 1,024；Append 缓存 2,048、计算新增 1,024。这不是同完整上下文比较；2K 历史是本机选择，论文未确认。
- 背景独立历史 128＋新增 4，输出 128；干扰输出 1；全部背景至少输出 8 token 后插入。每 trial 预热 B＋1 条历史，使用独立 salt；Full 使用冷 salt。
- `max_num_seqs=201`、`max_model_len=18432`、`gpu_memory_utilization=0.85` 不变。默认 V1/FCFS/连续批处理，启用 chunked prefill，观测器不修改调度。
- batch=10/100/200，每点三次重复，五组共 **135 trials、28,125 请求**；另有预算 2,048、16K 历史、B200 的独立先导 **3 trials、1,205 请求**。所有请求成功、缓存/计算量/实际 batch 验收通过，无抢占。
- 使用独立随机数流，使跨历史长度、预算和场景的背景完整输入与新增 1K 输入完全相同；2K 干扰历史是 16K 的前缀。已从原始请求逐一检查。
- 小预算三组先运行，再运行大预算两组；各组内部 batch/场景顺序随机化。不同预算位于两个时间块，不能完全排除时间漂移；原 16K 大预算配置在本轮重测，旧结果只作为历史参考。

模型步骤耗时是调度返回到输出交回的墙钟时间，不是纯 GPU kernel 时间。“累计额外模型耗时”针对每个 prefill 块减去按请求及输出 token 序号匹配的纯 decode 模型步骤，再对所有块求和；因此不会把多块带来的多轮正常 decode 时间误计为纯 prefill 成本。

客户端整段额外 TPOT 则直接用同重复的完整请求均值作差，包含所有正常、干扰和后续间隔；保留负差和尖峰，不通过改变窗口获取目标曲线。

## 显存与 GPU 观测

| token budget | KV 池 GiB | KV 容量 token | 正式请求期间采样显存 MiB |
|---:|---:|---:|---:|
| 2,048 | 4.60 | 86,048 | 21069–21071 |
| 17,664 | 3.35 | 62,800 | 21473–22933 |

预算降低后临时计算内存需求减少，KV 池增大；这与 Full 是否重新计算历史是不同维度。所有正式混合步骤都包含预期数量的背景 decode，无抢占。没有证据表明当前差距来自显存不足或换页。

保留约 0.5 秒间隔的 GPU、显存、功耗、温度、时钟采样，按实际请求 start/end 区间关联到 trial，排除预热和落盘阶段。`utilization.memory` 是显存访问活动指标，不是显存容量占比。采样有历史窗口且时间分辨率有限，不能据此判定单个短 chunk 的 SM／带宽瓶颈或证明 GPU 已饱和。每 trial 的采样统计在 `plot-data.json` 的 `trial_rows[].gpu_sampling`。
