# Phase 10：随背景 batch 增加 prefill 干扰次数

2026-11-23 UTC。用户已授权开始，并选择改用 dcn9。本阶段是 Phase 8 的单卡 Figure 2 适配实验，不涉及 PD 网络传输。三组先导和 130 组正式实验已完成，正式审计通过。

## 当前状态

因 dcn10 的 RTX 4090 正有其他计算任务运行，用户明确选择使用 dcn9。启动前 dcn9 无计算进程、GPU 利用率 0%，原有 Proxy 保留。Phase 10 使用独立服务端口 8300，背景请求和干扰均在 dcn9 同一 GPU 运行；客户端仍在 dcn10 的 CLI 内。客户端单调时钟仅用于客户端请求/SSE，服务端调度和 GPU 采样使用 dcn9 的单调时钟，不跨节点相减。

本地离线验证使用独立的合成时间戳和调度记录，核验 Full 跨两个 chunk 的计算量、整段 TPOT、五步与完整 chunk 窗口、SSE 合并 token 时的局部排除、超预算拒绝。这些数据仅验证分析代码，不是实验结果，不进入正式图。记录位于 `artifacts/phase10-multi-interference-evidence/offline-validation.json`。

先导包含 1,525 条请求，全部成功。实际 KV 池为 120,624 tokens，容量检查所需 114,240 tokens；调度最大 2,048 tokens、251 条序列，无抢占。Full 的 5 次干扰各分为 1,798＋378 tokens 两步，Append 各一步 128 tokens，全部干扰步骤包含 250 条背景 decode。先导不进入正式统计。

## 已确认的实验设计

模型 Qwen2.5-7B-Instruct，BF16，单 RTX 4090，复用 `ppd-qwen25:source-cu129`。只挂载实验观察代码，不覆盖镜像中的 `/opt/ppd/vllm-source` 编译目录。背景每条请求为独立 256-token 历史、32-token 新增，固定输出 128 tokens。每条干扰是独立 2,048-token 历史、128-token 新增，固定输出 1 token。

Append 使用已预热的历史 KV，实际计算新增 128 tokens。Full 发送相同的完整 2,176-token 输入，使用冷 cache salt，重算历史和新增。每 trial 清理 prefix cache；所有对照均预热同样数量、同样输入的背景与全部计划干扰历史，包括 Decode only 和单次干扰对照。不同请求 salt 独立，同 batch/repeat 的输入跨场景相同，实际 cache hit 必须由响应确认。

| 背景 batch | 多次干扰数 | 所有背景至少已输出的 token 数（发送触发点） |
|---:|---:|---|
| 10 | 1 | 8 |
| 50 | 1 | 8 |
| 100 | 2 | 8、104 |
| 150 | 3 | 8、56、104 |
| 200 | 4 | 8、40、72、104 |
| 250 | 5 | 8、32、56、80、104 |

每个 batch 比较 Decode only、Append、Full。batch≥100 另加单次 Append、单次 Full，复用对应多次实验的第一个干扰输入，触发点为 8。每条件 5 次重复，正式共 130 trials。另先运行 batch 250 的三个主场景各一次，作为容量和机制先导，不进入正式统计。按固定种子打乱条件顺序；失败保留并停止，不静默重试或缩小 batch。

调度为 vLLM V1 默认 FCFS 连续批处理，chunked prefill，`max_num_batched_tokens=2048`、`max_num_seqs=251`、`max_model_len=18432`、block size 16、prefix caching、eager。显存利用率先导尝试 0.94，启动日志的实际 KV 容量至少 114,240 tokens，并通过先导验证全部背景、全部干扰缓存和无抢占。

这两个调度上限不保证所有请求同一步运行：每条 decode 通常消耗一个预算 token，Full 的 2,176 tokens 超出整步预算，需分块；实际排队、chunk 数和混合背景数均从观察记录确认。运行器不修改调度决策。

## 统计与验收

- 主指标是**背景 decode** 的 `(最后 token 到达时间−首 token 到达时间)/127`，先对请求平均，再对 5 次重复取均值和样本标准差。干扰的 TTFT 单独保留，不充当背景 TPOT。
- 每条干扰以实际首个 prefill 调度步为零点，统计随后 1、5、16 个 decode step，以及覆盖全部 prefill chunks 的窗口；按相同背景编号、相同输出 token 序号匹配同重复的 Decode only。
- SSE 合并多个 token 时，不捏造各 token 到达时刻；受影响局部窗口标记缺失，整段端点统计保留。部分背景 batch 的局部步骤排除并记录，prefill 混合步骤必须包含全部 B 条背景。
- 多个事件窗口重叠时先按调度 step 去重，再计算累计影响。保留负的配对差异，不按期望趋势筛选数据。
- 每条请求保留原始输入、SSE、解析事件、响应与失败；保留请求 CSV/JSONL、调度 trace、metrics、服务日志、GPU 利用率/显存/功耗/温度/频率和源码哈希。
- 验收要求全部请求长度、缓存命中、实际计算量、事件数量/时点正确；调度不超预算，无抢占、OOM 或混合 batch 缺失。先导未通过则保存证据并暂停。

计划输出四组 PNG/SVG/PDF：全输出背景 TPOT、单次与多次干扰的配对超额 TPOT、五步窗口背景 TPOT、多事件逐步延迟轨迹。正式结果保存后才发布图，附可独立重画的数据、代码、说明。

增加干扰次数本身改变了负载；即使差异随 batch 上升，也不能仅凭该曲线声称验证了固定干扰下的硬件扩展机制，或完整复现原论文 4×H100 的 Figure 2。

## 正式结果与收尾

正式共 130 组、37,380 条请求全部成功（含 18,780 条预热、18,400 条背景、200 条干扰），输出合计 2,374,180 tokens。主实验 90 组，单次干扰对照 40 组，每条件 5 次重复，先导不混入结果。

下表为背景全输出 TPOT，均值±样本标准差，单位 ms/token。

| 背景 batch | 干扰数 | Decode only | Append | Full |
|---:|---:|---:|---:|---:|
| 10 | 1 | 17.98 ± 0.20 | 18.04 ± 0.21 | 19.30 ± 0.03 |
| 50 | 1 | 21.75 ± 1.06 | 21.33 ± 0.04 | 22.85 ± 0.22 |
| 100 | 2 | 24.74 ± 0.16 | 24.99 ± 0.09 | 28.05 ± 0.34 |
| 150 | 3 | 29.86 ± 0.34 | 30.53 ± 0.28 | 35.20 ± 0.60 |
| 200 | 4 | 37.26 ± 0.39 | 38.38 ± 0.42 | 44.54 ± 0.37 |
| 250 | 5 | 41.59 ± 0.36 | 42.73 ± 0.41 | 51.00 ± 0.07 |

单次与多次对照的配对超额均值如下，单位 ms/token：

| 背景 batch | Append 单次超额 | Append 多次超额 | Full 单次超额 | Full 多次超额 |
|---:|---:|---:|---:|---:|
| 100 | 0.33 | 0.25 | 1.62 | 3.31 |
| 150 | 0.27 | 0.67 | 1.82 | 5.33 |
| 200 | 0.49 | 1.11 | 1.94 | 7.28 |
| 250 | 0.64 | 1.13 | 1.68 | 9.40 |

batch 250 的 Full 单次背景 TPOT 为 43.27，五次为 51.00，基线 41.59；Append 单次 42.23，五次 42.73。增加干扰次数明显放大了 Full 的整段平均影响。主曲线随 batch 的间隔扩大包含干扰次数改变的因素，不能只解释为单次 prefill 的硬件干扰斜率。

全部 200 次干扰的缓存和计算量正确。Full 每次两块、累计 2,176 tokens，Append 每次一块 128 tokens；每个混合步骤都包含完整 B 条背景。最大调度 2,048 tokens、251 条序列，无抢占。日志无运行时 ERROR、CUDA OOM，容器 OOMKilled=false。

五步窗口 200/200 完整，1 步与完整 chunk 窗口也全部完整；16 步窗口 199/200，另一个因局部 batch 不完整保留为缺失。局部共排除 935 步，其中 748 步处理组背景不完整、187 步匹配基线不完整；整段 TPOT 不受这些排除影响。未发现 SSE 合并 token。所有配对负差异、异常间隔和重复散点保留。

图和可独立重画材料位于 [results/figures/phase10](../results/figures/phase10/README.md)。四组图分别为背景全输出 TPOT、单次与多次对照、实际调度后的五步窗口、完整输出逐步轨迹；均提供 PNG/SVG/PDF。逐步图统一纵轴，保留最高峰值。

GPU 测量期间显存采样均为 23,215 MiB，主要反映预分配，不能当作每步有效 KV 使用量；温度采样 59–76°C。0.5 秒 GPU 采样无法分辨单个 prefill chunk。调度观察在正式背景步骤平均约 0.154 ms，但有 10 步超过 50 ms，最大 109.88 ms；这些长尾没有删除，小幅整段差异可能受测量与运行噪声影响。

同条件控制的是精确输入和固定 128-token 输出长度，没有强制生成轨迹逐 token 一致。14,600 条处理组背景中 9,641 条正文与对应基线相同，不同动态 batch 的浮点数值路径可能改变后续生成；不能把输入配对描述为输出正文全部相同。详情在 measurement-diagnostics.json。

正式审计已经通过后，收尾的第二次 trace 导出只等待一秒便开始目录打包，562 MiB trace 尚在写入临时文件，tar 报 file changed。临时容器仍由 finally 清理。之后在服务停止、文件稳定后，重新导出明确命名的文件，SHA256 与正式审计原始 trace 一致，没有重跑任何模型请求。原始归档、事故说明与修复后工具副本保留。运行器已改为等待原子导出完成的确认，归档不含临时文件，并确保收尾清单记录。冻结的实际运行源码 source-code/ 保持原样；修复只影响导出收尾和最终绘图排版。

原 Proxy 保留，dcn10 的外部计算任务未操作。阶段结束只停止并删除本次 dcn9 临时模型容器。数据与代码同步完成后暂停，不提交或推送 Git，不启动下一阶段。
